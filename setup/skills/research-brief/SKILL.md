# Research Brief

Use `engineering-baseline` first. Browse or use authoritative docs when facts may be current, niche, high-stakes, or source-sensitive.

## Flow

1. Clarify the decision or question.
2. Identify what must be current or source-backed.
3. Prefer primary sources: official docs, specs, papers, source repos, changelogs.
4. Compare options against the user's context and constraints.
5. Produce a short brief with recommendation, alternatives, risks, and sources.

Do not guess current facts. If current accuracy matters, browse or use official docs. If source access is unavailable, say the answer is unverified.

## Output

- Recommendation
- Evidence
- Tradeoffs
- Risks / unknowns
- Next action
