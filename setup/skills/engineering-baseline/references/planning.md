# Planning Defaults

- Ground in the repo before asking questions that files can answer.
- Clarify goal, audience, success criteria, constraints, scope, and non-goals.
- Offer meaningful routes when the work can be approached several ways.
- Prefer plans that deliver working, testable increments.
- Do not create a detailed implementation plan while high-impact product or architecture choices are still open.
- For large/vague Claude Code planning, prefer Superpowers brainstorming and writing-plans when available.
- For Codex or lightweight planning, create a compact decision-complete plan with assumptions and tests.
