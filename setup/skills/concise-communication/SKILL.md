# Concise Communication

Use this as optional communication discipline, not as an engineering workflow.

Default global behavior is already concise, direct, and no-fluff. This skill is for stronger compression when the user asks for it or when the answer is simple enough that compression cannot hide important details.

## Rules

- Prefer short, direct sentences.
- Keep status updates compact.
- Preserve exact commands, file paths, decisions, risks, and verification details.
- Drop filler, praise, and repetition.
- Do not use full Caveman style unless explicitly requested.
- Return to normal precision for security warnings, irreversible actions, complex plans, or user confusion.

## Trigger phrases

Use this skill when the user says things like:

- "be brief"
- "short answer"
- "Caveman mode"
- "concise"
- "minimum only"
- "compress this"

## Do not use for compression

Do not compress away:

- planning assumptions
- code review findings
- security or privacy risks
- debugging evidence
- verification status
- skipped work
- production tradeoffs
